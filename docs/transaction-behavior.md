# Транзакции

## Распространение транзакций

`@Transactional` из Jakarta Transactions задаёт распространение транзакции (`TxType`), то есть поведение метода относительно уже активной транзакции. Уровень изоляции — отдельная настройка.

| `TxType` | Если вызывающий код уже в транзакции | Если активной транзакции нет |
| --- | --- | --- |
| `REQUIRED` | Присоединиться к ней | Начать новую |
| `REQUIRES_NEW` | Приостановить её и начать отдельную; после метода возобновить исходную | Начать новую |
| `MANDATORY` | Присоединиться к ней | Завершить вызов исключением |
| `SUPPORTS` | Присоединиться к ней | Выполниться без транзакции |
| `NOT_SUPPORTED` | Приостановить её и выполниться без транзакции | Выполниться без транзакции |
| `NEVER` | Завершить вызов исключением | Выполниться без транзакции |

Если значение в `@Transactional` не задано, используется `REQUIRED`.

В этом приложении нужны два режима:

- `REQUIRED` — операции записи: метод начинает транзакцию, если её нет, и присоединяется к существующей, если вызван в рамках другой транзакционной операции. Поэтому создание человека и билета может быть частью общей транзакции.
- `REQUIRES_NEW` — поиск билетов, где запрос общего количества и запрос страницы должны видеть один снимок данных независимо от транзакции вызывающего кода.

Остальные четыре режима сейчас не нужны: они либо заставили бы вызывающий код обязательно иметь/не иметь транзакцию, либо отключили бы транзакцию для метода.

## Изоляция

`TxType` не задаёт SQL-уровень изоляции. В Payara ресурс `jdbc/SharedDB` использует пул `SharedPoolA` с уровнем `READ_COMMITTED`; это настройка пула сервера. Для поиска билетов уровень повышается до `REPEATABLE_READ` через проектную CDI-аннотацию `@TransactionIsolation` и `TransactionIsolationInterceptor` из `se.ifmo.ru.isolation`.

Интерсептор выполняется после начала транзакции, проверяет, что транзакция активна, получает `StatelessSession` через `TicketRepository`, присоединяет её к JTA-транзакции и выполняет `SET TRANSACTION ISOLATION LEVEL ...` до вызова метода. Контракт аннотации требует `REQUIRES_NEW`: проверяется эффективная аннотация метода или класса, причём метод имеет приоритет. Проверка активной транзакции остаётся дополнительной защитой. PostgreSQL запрещает смену изоляции после первого запроса, поэтому до интерсептора изоляции другие интерсепторы не должны обращаться к БД. Прямой вызов метода внутри того же объекта не проходит через CDI и не создаёт новую границу транзакции.

## Транзакционные методы

| Метод | Распространение | Изоляция | Поведение |
| --- | --- | --- | --- |
| `TicketService.saveTicket` | `REQUIRED` | `READ_COMMITTED` | Сохраняет билет и при необходимости нового человека атомарно в одной транзакции. |
| `TicketService.sellWithDiscount` | `REQUIRED` | `READ_COMMITTED` | Читает исходный билет и создаёт билет со скидкой в одной транзакции. Внутренний вызов `saveTicket` — self-invocation, но уже открытую внешнюю транзакцию он использует. |
| `TicketService.deleteTicketById` | `REQUIRED` | `READ_COMMITTED` | Один DELETE возвращает число удалённых строк; ноль преобразуется в ошибку отсутствия билета. |
| `TicketService.updateTicket` | `REQUIRED` | `READ_COMMITTED` | Чтение и изменение билета входят в одну транзакцию. |
| `TicketService.search` | `REQUIRES_NEW` | `REPEATABLE_READ` | Количество и страница читаются в одной новой транзакции и одном снимке данных. |
| `TicketService.getTickets` | `REQUIRES_NEW` | `REPEATABLE_READ` | Та же гарантия для GET-списка; вызов `search` внутри того же объекта не открывает вторую транзакцию. |
| `PersonService.savePerson` | `REQUIRED` | `READ_COMMITTED` | Сохраняет человека; внутренний вызов `savePersonEntity` использует открытую транзакцию через self-invocation. |
| `PersonService.savePersonEntity` | `REQUIRED` | `READ_COMMITTED` | При вызове из `TicketService` через CDI присоединяется к транзакции создания билета. |
| `PersonService.deletePersonById` | `REQUIRED` | `READ_COMMITTED` | Проверка связей и удаление входят в одну транзакцию. |
| `PersonService.updatePerson` | `REQUIRED` | `READ_COMMITTED` | Чтение и изменение человека выполняются атомарно. |
| `EventCancellationService.cancelEvent` | `REQUIRED` | `READ_COMMITTED` | Удаление билетов события выполняется как одна транзакция. |

Независимые HTTP-запросы не присоединяются к транзакциям друг друга. `REQUIRED` присоединяет только вызовы внутри одной цепочки выполнения, если активная транзакция передана контейнером. `REQUIRES_NEW` приостанавливает такую транзакцию и выполняет метод отдельно.


Для REQUIRED уровень READ_COMMITTED в таблице означает настройку пула при начале новой транзакции. При присоединении метод наследует уровень уже активной транзакции.

Проверка вложенных CDI-вызовов: `tests/transaction-isolation/README.md`. На Payara 7/PostgreSQL 16 получены разные ID внешней и внутренней транзакций; после возврата восстановлены ID и READ COMMITTED внешней транзакции.
